# Changes

## 2026-11-15

- Added design document `docs/superpowers/specs/2026-11-15-kring-design.md`
  (Secret Service, offline keyring files, consolidate, KWallet migration, SSH, GPG).
- Added implementation plan 1 (foundation + Secret Service) in `docs/superpowers/plans/`.
- Scaffolded Cargo workspace (`kring-core`, `kring`), empty eframe window, and
  `scripts/check-no-gui-toolkits.sh` guard against GTK/Qt/GNOME crates.
- Added `kring-core` model types (`SecretValue` zeroized and redacted), `KringError`, and input validation.
- Added `SecretStore`/`MasterPasswordStore` traits and in-memory `FakeStore` (feature `fake`).
- Added `scripts/it-session.sh` (private dbus session + throwaway gnome-keyring) and the `it_smoke` integration test.
- Added Secret Service backend (`SecretServiceBackend`, standard API via oo7, encrypted session) with D-Bus error mapping; integration tests guarded by `it_guard` (session script now exports `KRING_IT_RUNTIME`).
- Added provider detection (`ProviderKind`, `detect`, `classify`) and PAM detection (`pam_status`), with an `it_provider` integration test.
- Added gnome-keyring master password support (`MasterPasswordStore` for `SecretServiceBackend`: create, unlock and change password via the private interface over a dedicated encrypted session, no prompts) with the `it_master_password` integration test.
- Added backups (`BackupManager`, age-encrypted plaintext keyrings, manifest with sha256, pruning) and `paths` helpers.
- Added the `kring` app library with `worker` (background thread, command/event channels, provider gating, backup before deletes, NotFound refresh).
- Added `app_state` (event reducer with sorted collections), `clipboard` (30 s auto-clear guard over arboard) and `secret_display` (text vs hex view).
- Added the egui UI (`KringApp`): sidebar with collections and disabled future sections, collection header with badges and PAM notices, item table with search, item detail (masked secret, Show/Hide, Copy with 30 s auto-clear, editable attributes), modal dialogs (unlock, create, rename, change password, delete confirmations, new/edit item, backup passphrase) with zeroized password buffers, provider gating tooltips and a status bar.
- Added `startup::connect` (keeps the D-Bus runtime alive for the worker) with the `it_startup` integration test, the `it_master_password` check that locked collections list their items as locked, the `seed_dev` example and `scripts/dev-session.sh` for isolated manual testing.
- Unified the private-session safety guard in `kring_core::dev_guard` (feature `dev`), used by both crates' integration tests and `seed_dev`; "Save attributes" now confirms the listed attribute changes (`attribute_diff`); deleting the login or default collection shows a warning; split dialog validation (`dialog_submit`) and the copy flow (`copy_flow::SecretCopier`) into their own modules.
- Final review fixes: deletes fail closed unless the target collection's `<name>.keyring` is in the backup (the in-memory `session` collection needs none); backup pruning is best-effort (`BackupInfo::prune_warning`, reported by the worker without blocking the delete) and source bytes are zeroized; master password calls ignore a session close failure after the call; item listing tolerates `IsLocked` properties (item reported locked); the clipboard copies with `exclude_from_history` and clears a pending secret when the guard is dropped (app exit); worker startup runs under the panic guard; successful mutations emit `Event::Done` for the status bar; added the `it_delete_backup` integration test.
- Delete backups decode gnome-keyring's `_XX` object path escapes (`model::decode_path_segment`) to find `<name>.keyring` (e.g. `Default_5fkeyring` -> `Default_keyring.keyring`); the collection display-name fallback is decoded too. Backups are ordered for listing and pruning by manifest `created` then the new `seq` counter (`#[serde(default)]`), not by directory name; directories with an unreadable manifest are never pruned.
- Restyled the UI in Paranoid Password Manager's "Obsidian" design system: new `ui` module (`theme` tokens copied verbatim with IBM Plex fonts under the SIL OFL and a WCAG contrast test, painter `glyphs`, `widgets`, `password_field` with show/hide eye, `toasts`); 64 px nav rail with brand tile, future areas dimmed and a worker activity dot; "Keyrings" list panel with `+ New`, search and selectable rows with DEFAULT/LOGIN chips; detail pane with chip header, icon actions, accent-bar notes and banners, and expandable item cards (secret box, attribute editor, Edit/Delete/Save); styled modal dialogs; toasts replace the status bar (`AppState::drain_messages`). Window 1280x800 (min 960x600), dark only. Dev-only screenshot presets `KRING_DEV_SELECT/EXPAND/REVEAL/DIALOG` are read only inside the isolated session (`KRING_IT_RUNTIME`).
- Restyle review fixes: screenshot presets moved to `dev_preset.rs`, compiled only in debug builds and honoured only when `kring_core::dev_guard::violation_from` accepts the environment (`violation_from` is now always compiled; the env reader stays behind the `dev` feature); `KRING_DEV_EXPAND` indexes cards in displayed order; danger button tints lowered (hover 0.14, pressed 0.20) with composited button states in the contrast test; buttons split into `ui/buttons.rs`; rustdoc on public fields and variants.
- Added implementation plan 2 (offline keyring files, recovery, backups UI, encrypted export).
- Added the tolerant textual keyring parser (`keyring_file::textual`): recovers multi-line `secret=` values that GLib and oo7 reject, reports `ParseWarning`s and a `daemon_readable` flag.
- Added `keyring_file::scan` (`detect_format`, `scan_dir`, `KeyringFileInfo`) and synthetic textual keyring fixtures under `crates/kring-core/tests/fixtures/keyrings/`.
- Textual parser fix round: only the first physical line of a value is GLib-unescaped (continuation lines verbatim), values built in `Zeroizing`, `KeyringFileInfo.error` and `plaintext` for any non-binary file, more edge and no-panic tests.
- Added binary v0 keyring reader (`keyring_file::binary::read_binary`, oo7 `load_from_v0`, in memory only) with wrong-password and not-binary errors, and the `make_binary_fixture` example (private session only) that generated `binary_two_items.keyring`.
- Added `transfer::import` (`plan_import`, `import_items`, `ImportReport`): imports offline items into an unlocked collection, skipping duplicates and listing same-attribute different-secret conflicts (attribute equality ignores `xdg:content-type`), continuing after per-item failures.
- Added `transfer::archive` (`write_archive`, `read_archive`, `ExportedItem`): age scrypt-passphrase item export/import (`kring-items` v1 JSON, base64 secrets, `Zeroizing` buffers, 0600, temp + hard link so an existing file is never overwritten); shared `backup` helpers `io_err`, `write_private`, `encrypt_age` made `pub(crate)`.
- Split `backup` into a module directory (`create`, `restore`) and added `backup::restore` / `read_backup_file` / `RESTART_HINT`: restores keyring files into the keyrings dir only after validating names (`*.keyring` or `default`), decrypting and sha256-checking every file, and backing up the current files (reason `pre-restore`, aborting on failure); atomic temp + rename writes at 0600; partial restore is possible only on I/O failure and the error lists the restored files.
- Added `keyring_file::retire` (`RetireMode`, `retire_mode`, `retire_file`) and `model::encode_path_segment`: a plaintext keyring file is deleted only after an age-encrypted backup (reason `retire-plaintext`) whose manifest sha256 matches the current file; refuses live, binary and changed-since-scan files. `retire_file` also takes `keyrings_dir` and `live: &[CollectionInfo]`; it only touches regular non-symlink `*.keyring` files directly in the keyrings dir, decides binary from the bytes, requires an encrypted manifest entry, and re-checks size/mtime right before the unlink.
- Added worker commands for offline features (`worker_offline.rs`): `ScanFiles`, `OpenFile`, `ImportFile`, `RetireFile`, `ListBackups`, `RestoreBackup`, `ExportCollection`, `ImportArchive` with events `Files`, `FileItems`, `PasswordNeeded(name)` (binary file opened without password), `ImportDone`, `Backups`, `RestoreDone`. File names resolve only to scanned regular `<keyrings_dir>/<name>.keyring` files (no `/`, `.`, `..`, symlinks); retiring a live collection reuses the gated `DeleteCollection` flow with backup, and a failing `list_collections` aborts the retire; restores accept only listed backup dirs and manifest files. `AppState` gains `files`, `selected_file`, `file_items`/`file_warnings` (secrets, cleared by `select_file`/`close_file` and when the file disappears), `pending_file_password`, `backups`, `last_import`, `last_restore`. Worker unit tests moved to `worker/tests.rs`.
- Added the Offline files area (rail folder tile now enabled): "Keyring files" list (`views/files_list.rs`: rescan, search, `files_summary`, `file_chips` BINARY/PLAINTEXT/UNREADABLE/EMPTY/UNKNOWN, size, quick Retire on empty orphan files) and file detail (`views/file_detail.rs`: header with path/size/date, plaintext/unreadable/live notes, "Import into..." and "Retire file", encrypted-file Open card, import conflicts card) with read-only item cards (`views/file_items.rs`, `FileView`: secrets hidden by default, shown per card from local state, copy via `SecretCopier::copy_value`). New dialogs: file password (resends Open or Import), import target combo (locked keyrings disabled, default unlocked `login`), retire confirmation with a confirmed backup passphrase (`retire_dialog_text`). `AppState` tracks `pending_file_action` (`track_file_command`, `take_password_request`; a password request opens only for the selected file and is dropped on error or file change), turns `ImportDone` into a toast (`import_summary`) and clears `last_import` with the file; `switch_area` closes the file (dropping its secrets) when leaving the area and rescans on entry. Toasts show errors without the `KringError` category prefix (`user_message`); offline commands needing a store report "No Secret Service provider running" verbatim. Dev presets `KRING_DEV_AREA=files`, `KRING_DEV_FILE`, `KRING_DEV_DIALOG=import|retire|open`; `scripts/dev-session.sh` copies the synthetic fixtures into the temp keyrings dir before the daemon starts. Added the `Refresh` glyph.
- Added the Backups area (rail Tools tile replaced by an enabled Backups tile with the new `Archive` glyph; `views/backups.rs`): backups newest first with humanized reason, local creation time (`local_time`, offset captured at startup), file count and size; the detail lists the files with an ENCRYPTED chip and checkboxes (all checked by default) and `Restore selected` opens a confirmation listing every `<keyrings_dir>/<file name>` that will be overwritten, asking the backup passphrase when an encrypted copy is restored or a new confirmed one when a plaintext destination must be backed up (`restore_passphrase`); the worker's `PassphraseNeeded` for a restore resends it with a single passphrase field. Added `README.md` (features, dev session, real use, safety notes).
- Plan 2 final review fixes: pruning never deletes the only copy of data. A backup is pinned (never pruned, not counted toward `keep`) when one of its manifest originals no longer exists, and a restore prunes only after its write phase succeeded, always sparing its source backup (`create_unpruned`, `prune_into`). `BackupInfo::pruned` lists the removed dirs and the app shows "Removed N old backups" as an info toast (`AppState::drain_notices`). Listed backups take `dir` from the scanned directory, not from the manifest, and `read_backup_file` refuses a stored copy that is a symlink or not directly inside the backup dir. A restore creates a missing keyrings dir with mode 0700. `OfflineItem::secret_missing` marks items whose file had neither `secret` nor `binary-secret`: the file view shows "No secret in file" instead of the secret controls, imports skip and count them (`ImportReport::no_secret`, toast `..., M without secret`) and they never take part in duplicate or conflict detection. The "lines were joined" note counts only continuation lines. The worker refuses to retire binary or non-plaintext files before the live-collection branch. `read_binary` reads only the 16 magic bytes before oo7, `summarize_dir` wipes file bytes on drop. An unrelated error no longer drops the pending file command; it is cleared by a file change, the file's items or taking the password request.
