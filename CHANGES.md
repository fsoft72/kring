# Changes

## 2026-11-15

- Added design document `docs/superpowers/specs/2026-11-15-kring-design.md`
  (Secret Service, offline keyring files, consolidate, KWallet migration, SSH, GPG).
- Added implementation plan 1 (foundation + Secret Service) in `docs/superpowers/plans/`.
- Scaffolded Cargo workspace (`kring-core`, `kring`), empty eframe window, and
  `scripts/check-no-gui-toolkits.sh` guard against GTK/Qt/GNOME crates.
- Added `kring-core` model types (`SecretValue` zeroized and redacted), `KringError`, and input validation.
- Added `SecretStore`/`MasterPasswordStore` traits and in-memory `FakeStore` (feature `fake`).
- Added `scripts/it-session.sh` (private dbus session + throwaway gnome-keyring) and the `it_smoke` integration test.
- Added Secret Service backend (`SecretServiceBackend`, standard API via oo7, encrypted session) with D-Bus error mapping; integration tests guarded by `it_guard` (session script now exports `KRING_IT_RUNTIME`).
- Added provider detection (`ProviderKind`, `detect`, `classify`) and PAM detection (`pam_status`), with an `it_provider` integration test.
- Added gnome-keyring master password support (`MasterPasswordStore` for `SecretServiceBackend`: create, unlock and change password via the private interface over a dedicated encrypted session, no prompts) with the `it_master_password` integration test.
- Added backups (`BackupManager`, age-encrypted plaintext keyrings, manifest with sha256, pruning) and `paths` helpers.
- Added the `kring` app library with `worker` (background thread, command/event channels, provider gating, backup before deletes, NotFound refresh).
- Added `app_state` (event reducer with sorted collections), `clipboard` (30 s auto-clear guard over arboard) and `secret_display` (text vs hex view).
- Added the egui UI (`KringApp`): sidebar with collections and disabled future sections, collection header with badges and PAM notices, item table with search, item detail (masked secret, Show/Hide, Copy with 30 s auto-clear, editable attributes), modal dialogs (unlock, create, rename, change password, delete confirmations, new/edit item, backup passphrase) with zeroized password buffers, provider gating tooltips and a status bar.
- Added `startup::connect` (keeps the D-Bus runtime alive for the worker) with the `it_startup` integration test, the `it_master_password` check that locked collections list their items as locked, the `seed_dev` example and `scripts/dev-session.sh` for isolated manual testing.
- Unified the private-session safety guard in `kring_core::dev_guard` (feature `dev`), used by both crates' integration tests and `seed_dev`; "Save attributes" now confirms the listed attribute changes (`attribute_diff`); deleting the login or default collection shows a warning; split dialog validation (`dialog_submit`) and the copy flow (`copy_flow::SecretCopier`) into their own modules.
- Final review fixes: deletes fail closed unless the target collection's `<name>.keyring` is in the backup (the in-memory `session` collection needs none); backup pruning is best-effort (`BackupInfo::prune_warning`, reported by the worker without blocking the delete) and source bytes are zeroized; master password calls ignore a session close failure after the call; item listing tolerates `IsLocked` properties (item reported locked); the clipboard copies with `exclude_from_history` and clears a pending secret when the guard is dropped (app exit); worker startup runs under the panic guard; successful mutations emit `Event::Done` for the status bar; added the `it_delete_backup` integration test.
- Delete backups decode gnome-keyring's `_XX` object path escapes (`model::decode_path_segment`) to find `<name>.keyring` (e.g. `Default_5fkeyring` -> `Default_keyring.keyring`); the collection display-name fallback is decoded too. Backups are ordered for listing and pruning by manifest `created` then the new `seq` counter (`#[serde(default)]`), not by directory name; directories with an unreadable manifest are never pruned.
- Restyled the UI in Paranoid Password Manager's "Obsidian" design system: new `ui` module (`theme` tokens copied verbatim with IBM Plex fonts under the SIL OFL and a WCAG contrast test, painter `glyphs`, `widgets`, `password_field` with show/hide eye, `toasts`); 64 px nav rail with brand tile, future areas dimmed and a worker activity dot; "Keyrings" list panel with `+ New`, search and selectable rows with DEFAULT/LOGIN chips; detail pane with chip header, icon actions, accent-bar notes and banners, and expandable item cards (secret box, attribute editor, Edit/Delete/Save); styled modal dialogs; toasts replace the status bar (`AppState::drain_messages`). Window 1280x800 (min 960x600), dark only. Dev-only screenshot presets `KRING_DEV_SELECT/EXPAND/REVEAL/DIALOG` are read only inside the isolated session (`KRING_IT_RUNTIME`).
- Restyle review fixes: screenshot presets moved to `dev_preset.rs`, compiled only in debug builds and honoured only when `kring_core::dev_guard::violation_from` accepts the environment (`violation_from` is now always compiled; the env reader stays behind the `dev` feature); `KRING_DEV_EXPAND` indexes cards in displayed order; danger button tints lowered (hover 0.14, pressed 0.20) with composited button states in the contrast test; buttons split into `ui/buttons.rs`; rustdoc on public fields and variants.
- Added implementation plan 2 (offline keyring files, recovery, backups UI, encrypted export).
- Added the tolerant textual keyring parser (`keyring_file::textual`): recovers multi-line `secret=` values that GLib and oo7 reject, reports `ParseWarning`s and a `daemon_readable` flag.
- Added `keyring_file::scan` (`detect_format`, `scan_dir`, `KeyringFileInfo`) and synthetic textual keyring fixtures under `crates/kring-core/tests/fixtures/keyrings/`.
