- Added `startup::connect` (keeps the D-Bus runtime alive for the worker) with the `it_startup` integration test, the `it_master_password` check that locked collections list their items as locked, the `seed_dev` example and `scripts/dev-session.sh` for isolated manual testing.
- Unified the private-session safety guard in `kring_core::dev_guard` (feature `dev`), used by both crates' integration tests and `seed_dev`; "Save attributes" now confirms the listed attribute changes (`attribute_diff`); deleting the login or default collection shows a warning; split dialog validation (`dialog_submit`) and the copy flow (`copy_flow::SecretCopier`) into their own modules.
- Final review fixes: deletes fail closed unless the target collection's `<name>.keyring` is in the backup (the in-memory `session` collection needs none); backup pruning is best-effort (`BackupInfo::prune_warning`, reported by the worker without blocking the delete) and source bytes are zeroized; master password calls ignore a session close failure after the call; item listing tolerates `IsLocked` properties (item reported locked); the clipboard copies with `exclude_from_history` and clears a pending secret when the guard is dropped (app exit); worker startup runs under the panic guard; successful mutations emit `Event::Done` for the status bar; added the `it_delete_backup` integration test.
- Delete backups decode gnome-keyring's `_XX` object path escapes (`model::decode_path_segment`) to find `<name>.keyring` (e.g. `Default_5fkeyring` -> `Default_keyring.keyring`); the collection display-name fallback is decoded too. Backups are ordered for listing and pruning by manifest `created` then the new `seq` counter (`#[serde(default)]`), not by directory name; directories with an unreadable manifest are never pruned.

Window 1280x800 (min 960x600), dark only. Dev-only screenshot presets `KRING_DEV_SELECT/EXPAND/REVEAL/DIALOG` are read only inside the isolated session (`KRING_IT_RUNTIME`).

- Added binary v0 keyring reader (`keyring_file::binary::read_binary`, oo7 `load_from_v0`, in memory only) with wrong-password and not-binary errors, and the `make_binary_fixture` example (private session only) that generated `binary_two_items.keyring`.
- Added `transfer::import` (`plan_import`, `import_items`, `ImportReport`): imports offline items into an unlocked collection, skipping duplicates and listing same-attribute different-secret conflicts (attribute equality ignores `xdg:content-type`), continuing after per-item failures.
- Added `transfer::archive` (`write_archive`, `read_archive`, `ExportedItem`): age scrypt-passphrase item export/import (`kring-items` v1 JSON, base64 secrets, `Zeroizing` buffers, 0600, temp + hard link so an existing file is never overwritten); shared `backup` helpers `io_err`, `write_private`, `encrypt_age` made `pub(crate)`.
- Split `backup` into a module directory (`create`, `restore`) and added `backup::restore` / `read_backup_file` / `RESTART_HINT`: restores keyring files into the keyrings dir only after validating names (`*.keyring` or `default`), decrypting and sha256-checking every file, and backing up the current files (reason `pre-restore`, aborting on failure); atomic temp + rename writes at 0600; partial restore is possible only on I/O failure and the error lists the restored files.
- Added `keyring_file::retire` (`RetireMode`, `retire_mode`, `retire_file`) and `model::encode_path_segment`: a plaintext keyring file is deleted only after an age-encrypted backup (reason `retire-plaintext`) whose manifest sha256 matches the current file; refuses live, binary and changed-since-scan files. `retire_file` also takes `keyrings_dir` and `live: &[CollectionInfo]`; it only touches regular non-symlink `*.keyring` files directly in the keyrings dir, decides binary from the bytes, requires an encrypted manifest entry, and re-checks size/mtime right before the unlink.

File names resolve only to scanned regular `<keyrings_dir>/<name>.keyring` files (no `/`, `.`, `..`, symlinks); retiring a live collection reuses the gated `DeleteCollection` flow with backup, and a failing `list_collections` aborts the retire; restores accept only listed backup dirs and manifest files. `AppState` gains `files`, `selected_file`, `file_items`/`file_warnings` (secrets, cleared by `select_file`/`close_file` and when the file disappears), `pending_file_password`, `backups`, `last_import`, `last_restore`. - Plan 2 final review fixes: pruning never deletes the only copy of data. A backup is pinned (never pruned, not counted toward `keep`) when one of its manifest originals no longer exists, and a restore prunes only after its write phase succeeded, always sparing its source backup (`create_unpruned`, `prune_into`). `BackupInfo::pruned` lists the removed dirs and the app shows "Removed N old backups" as an info toast (`AppState::drain_notices`). Listed backups take `dir` from the scanned directory, not from the manifest, and `read_backup_file` refuses a stored copy that is a symlink or not directly inside the backup dir. A restore creates a missing keyrings dir with mode 0700. `OfflineItem::secret_missing` marks items whose file had neither `secret` nor `binary-secret`: the file view shows "No secret in file" instead of the secret controls, imports skip and count them (`ImportReport::no_secret`, toast `..., M without secret`) and they never take part in duplicate or conflict detection. The "lines were joined" note counts only continuation lines. The worker refuses to retire binary or non-plaintext files before the live-collection branch. `read_binary` reads only the 16 magic bytes before oo7, `summarize_dir` wipes file bytes on drop. An unrelated error no longer drops the pending file command; it is cleared by a file change, the file's items or taking the password request.
- Added implementation plan 3 (copy, move, conflict preview, consolidate).
- Plan 3: added the source-agnostic transfer planner (`transfer::plan`: `plan_transfer`, `Incoming`/`Existing`, conflicts with newest-preselected default); `plan_import` now runs on top of it with unchanged behavior.
- Plan 3: added the transfer executor (`transfer::apply`: `apply_transfer`, `TransferMode`, `TransferReport`, pure `source_safe_to_delete`). Move deletes only live sources whose content is in the target (created, duplicate, UseIncoming applied, same-batch duplicate of a successful create) or, for a conflict resolved as KeepTarget with an equal or newer target, whose incoming secret survives only in the pre-apply backup (callers must back up source and target first); NoSecret and ConflictSameBatch sources are kept, and a Move into the source's own collection is refused. Added a planner test for several existing items sharing an identity.
- Plan 3: added the consolidation planner (`transfer::consolidate`: `plan_consolidation`, `CollectionSnapshot`, `MoveStep`, `ConsolidationPlan`, `SkipReason`). Target, login, session, alias paths and locked collections are skipped; empty readable orphans are listed for deletion; each non-empty orphan becomes a move step planned against the target plus items planned by earlier steps (placeholder ids `planned:<step>:<index>`), so an item shared by two orphans is created once.
- Plan 3: added the consolidation executor (`transfer::consolidate_apply`: `apply_consolidation`, `StepOutcome`, `ConsolidationReport`). Runs moves, then deletes each move source only when empty now (else `Kept`), then the planned-empty collections (re-checked; non-empty fails the run), then the `default` alias; stops on the first failure. Each move step is re-planned against the live source and target, choices are matched by incoming index; items changed since the preview or in a conflict the preview did not show stay in their source. Plans naming the target, login, session or alias paths for deletion are refused.
- Plan 3 consolidation review fixes: a KeepTarget choice whose preview showed the target as older keeps the source (judged on the preview, since items created or updated by earlier steps are stamped with the current time); a partly failed move step reports its partial `Moved` outcome before `Failed`; offline items in a move step are refused with `InvalidInput`; a target that reports locked is refused even when its items were read.
- Plan 3: added `retire_files_batch` (`RetireBatchReport`): retires many plaintext non-live keyring files with one encrypted backup; files failing the shared pre-checks (now `precheck`, also used by `retire_file`), manifest verification or the pre-unlink unchanged check are kept and listed; `backup` is `None` when no file passed the pre-checks.
- Plan 3: the worker plans, previews and applies transfers and consolidations (`worker_transfer`, `worker_transfer/consolidate.rs`). New commands `PlanTransfer`, `PlanFileImport`, `PlanArchiveImport`, `ApplyTransfer`, `PlanConsolidation`, `ApplyConsolidation`, `DiscardPlan`; events `TransferPreview`, `TransferDone`, `ConsolidationPreview`, `ConsolidationProgress`, `ConsolidationDone` with secret-free `ConflictView` / `ConsolidationSummary` (planned target items have no id and are never revealed; `RevealSecret` refuses `planned:` ids). One pending plan per worker, dropped by any mutating command; a stale or unknown id is refused ("Plan is out of date, preview again"), while a passphrase request keeps the plan valid. `backup_collections` generalizes `backup_before` (ONE backup, every named collection's keyring file required, fail closed): Move backs up target and sources, `UseIncoming` the target, consolidation the target, every move source and every empty collection to delete; copy without `UseIncoming` takes none. Move into the items' own collection is refused at plan time and live sources changed since the preview stop the apply. `ImportFile` / `ImportArchive` (aliases of the new plan commands) apply directly when there are no conflicts (Plan 2 `ImportDone`) and otherwise preview. After a completed consolidation the previewed empty plaintext orphan files are retired in one batch. `AppState` keeps the previews, progress and reports (`transfer_summary`, `consolidation_status`). Core: `retire_files_batch` de-duplicates its input by path and `RetireBatchReport` is `Clone`.
- Plan 3 worker review fixes: apply commands are never echoed in `PassphraseNeeded`; the new `Event::ApplyPassphrasesNeeded { plan_id, backup, orphan_files }` asks for the missing passphrases and keeps the plan valid. Plan 1/2 echoes go through `passphrase_echo`, which clears the passphrase fields. Changed-source detection also compares labels. `AppState` previews replace each other, a stale-plan error clears them, and any error clears the consolidation progress.
