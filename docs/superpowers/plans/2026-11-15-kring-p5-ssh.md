# kring Plan 5: SSH keys and ssh-agent

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manage the user's SSH keys in `~/.ssh` (list, inspect, generate, import, export, change passphrase, delete with backup) and the keys loaded in `ssh-agent` (list, add, remove), in the Obsidian UI, with the session-remembered passphrase and the progress modal from Plan 4.

**Architecture:** `kring-core::ssh` (pure-Rust key files via `ssh-key` 0.6 with `ed25519, p256, p384, rsa, encryption, getrandom` features; a minimal ssh-agent protocol client over the Unix socket using `ssh-encoding`). Worker commands in `worker_ssh.rs`; UI area "SSH keys" (rail tile already present).

**Tech Stack:** as before plus `ssh-key = { version = "0.6", features = [...] }` (verify it pulls no GUI toolkit; check the toolkit guard).

**Spec:** `docs/superpowers/specs/2026-11-15-kring-design.md` section 6.7 (and 2.5).

## Findings (user's system, read-only)

- `~/.ssh`: `id_ed25519`, `id_rsa` (OpenSSH private key format), their `.pub`, `authorized_keys`, `config`, `known_hosts`. `SSH_AUTH_SOCK` points to a running ssh-agent with no identities loaded. `ssh-keygen`, `ssh-add`, `ssh-agent` are installed (use them only in tests/fixture generation inside temp dirs, never against the user's files or agent).

## Global Constraints

- All previous constraints (no GUI toolkits, SecretValue/zeroize, no secrets in events except dedicated secret events, English, rustdoc, early returns, UPPER_SNAKE, no long dash, rustfmt, Conventional Commits without AI attribution, tests never touch real data).
- **Never read or write the user's real `~/.ssh` or talk to the user's real agent in tests/tools.** Tests use temp dirs and a private `ssh-agent -a <tmp socket>` started by the test (killed at the end). `scripts/dev-session.sh` must start a private ssh-agent, export its `SSH_AUTH_SOCK` and seed a temp `~/.ssh` with fixture keys.
- `WorkerConfig.ssh_dir` (default `$HOME/.ssh`) and `WorkerConfig.ssh_agent_sock: Option<PathBuf>` (default from `SSH_AUTH_SOCK` at startup).
- Key files: private `0600`, public `0644`, written via temp + rename in the same dir, never overwriting an existing file except "change passphrase" (which replaces the private key after a backup).
- Delete moves files to a backup (spec 6.7): reuse `BackupManager` with reason `delete-ssh-key`; an UNENCRYPTED private key is plaintext and must be stored age-encrypted (extend BackupManager's plaintext rule with an explicit "sensitive" flag per file rather than the `.keyring` extension heuristic; keep keyring behavior unchanged).
- Only files recognised as SSH keys are touched (private key = parses as OpenSSH private key; public = parses as OpenSSH public key). `authorized_keys`, `known_hosts`, `config` are never listed as keys and never modified.
- Legacy PEM / PKCS#8 private keys are listed as "legacy format" (read-only, no actions except delete).
- Passphrases: SecretValue; the session-remembered passphrase (Plan 4 UX) works for unlock-to-add-to-agent and change-passphrase (old passphrase) dialogs; wrong passphrase reopens the dialog (shared constant).
- Destructive operations (delete, change passphrase, remove from agent? (not destructive: agent removal is non-persistent; no modal needed)) go through the progress modal.

## Review Focus

1. No path ever touches files outside `ssh_dir` or non-key files (authorized_keys, known_hosts, config). Task 1/2.
2. Unencrypted private keys never written unencrypted into backups. Task 2.
3. Agent client: correct protocol framing, no panic on malformed replies, never talks to the real agent in tests. Task 3.
4. Private key material only in SecretValue / Zeroizing; never in events except the explicit export flow. Tasks 2-4.
5. Wrong passphrase handling consistent with Plan 4 (reopen dialog, remembered passphrase rules). Task 5.

### Task 1: Key scanning and inspection

**Files:** `crates/kring-core/src/ssh/{mod.rs,scan.rs}`, fixtures `crates/kring-core/tests/fixtures/ssh/` generated with `ssh-keygen` (ed25519 unencrypted, ed25519 encrypted with passphrase `fixture-pw`, rsa 3072, ecdsa p256, a legacy PEM rsa via `ssh-keygen -m PEM`, an orphan `.pub`, plus `authorized_keys`/`known_hosts`/`config` decoys) with a README describing how they were made.

**Interfaces:**
- `pub enum SshAlgorithm { Ed25519, EcdsaP256, EcdsaP384, EcdsaP521, Rsa, Other(String) }`
- `pub struct SshKeyInfo { pub name: String /* file stem */, pub private_path: Option<PathBuf>, pub public_path: Option<PathBuf>, pub algorithm: SshAlgorithm, pub bits: Option<u32>, pub fingerprint: String /* SHA256:... */, pub comment: String, pub encrypted: Option<bool> /* None if no private key */, pub legacy_format: bool }`
- `pub fn scan_keys(dir: &Path) -> Result<Vec<SshKeyInfo>>`: regular files only (no symlinks), pairs `<name>` + `<name>.pub`; never reads non-key files beyond the format probe; fingerprint/algorithm from the public key (or from the private key's public part when `.pub` is missing; encrypted private keys still expose their public key in the OpenSSH format).
- Tests on the fixtures (all fields), decoys ignored, symlinks ignored, missing dir -> empty.
- Commit `feat(core): scan and inspect SSH keys`.

### Task 2: Key operations

**Files:** `crates/kring-core/src/ssh/ops.rs`, `crates/kring-core/src/backup/create.rs` (sensitive flag).

**Interfaces:**
- `pub struct NewKey { pub name: String, pub algorithm: SshAlgorithm /* Ed25519 | EcdsaP256 | EcdsaP384 | Rsa */, pub rsa_bits: u32 /* 3072|4096 */, pub comment: String, pub passphrase: Option<SecretValue> }`
- `pub fn generate_key(dir: &Path, key: &NewKey) -> Result<SshKeyInfo>` (name validated: `[A-Za-z0-9._-]+`, not existing, not a reserved file name).
- `pub fn import_key(dir: &Path, source: &Path, name: Option<&str>) -> Result<SshKeyInfo>` (validates it parses; copies private (+ public, derived if missing); refuses overwrite).
- `pub fn export_public(info: &SshKeyInfo) -> Result<String>` (OpenSSH one-line); `pub fn export_private(info: &SshKeyInfo, dest: &Path, passphrase: Option<&SecretValue> /* to decrypt */, new_passphrase: Option<&SecretValue> /* to encrypt the exported copy */) -> Result<()>` (create_new, 0600).
- `pub fn change_passphrase(manager: &BackupManager, dir: &Path, info: &SshKeyInfo, old: Option<&SecretValue>, new: Option<&SecretValue> /* None = remove encryption, require explicit flag in UI */, backup_passphrase: Option<&SecretValue>) -> Result<BackupInfo>`: backup first (sensitive if currently unencrypted), then atomic replace of the private file.
- `pub fn delete_key(manager: &BackupManager, dir: &Path, info: &SshKeyInfo, backup_passphrase: Option<&SecretValue>) -> Result<BackupInfo>`: backup private+public (private sensitive when unencrypted -> age), verify manifest (sha256, encrypted when sensitive), then remove both.
- `pub const MSG_WRONG_KEY_PASSPHRASE: &str = "Wrong key passphrase";`
- Tests (tempdirs, fixtures copied): generate each algorithm (+ encrypted), import, export public/private (re-encrypted copy decrypts with the new passphrase), change passphrase (old wrong -> MSG_WRONG_KEY_PASSPHRASE, nothing changed; backup exists), delete (backup with age for unencrypted private; files gone), refuse decoys/symlinks/outside dir.
- Commit `feat(core): SSH key operations with backups`.

### Task 3: ssh-agent client

**Files:** `crates/kring-core/src/ssh/agent.rs` (+ integration test using a private agent).

**Interfaces:**
- `pub struct AgentIdentity { pub fingerprint: String, pub comment: String, pub algorithm: SshAlgorithm }`
- `pub fn list_identities(sock: &Path) -> Result<Vec<AgentIdentity>>` (SSH2_AGENTC_REQUEST_IDENTITIES = 11 -> SSH2_AGENT_IDENTITIES_ANSWER = 12).
- `pub fn add_identity(sock: &Path, info: &SshKeyInfo, passphrase: Option<&SecretValue>, lifetime_secs: Option<u32>) -> Result<()>` (SSH2_AGENTC_ADD_IDENTITY = 17 / ADD_ID_CONSTRAINED = 25 with lifetime; SUCCESS = 6, FAILURE = 5).
- `pub fn remove_identity(sock: &Path, public_key_blob) -> Result<()>` (18), `pub fn remove_all(sock: &Path) -> Result<()>` (19).
- Blocking UnixStream with timeouts (5 s); message length cap (256 KiB) to avoid huge allocations; private key serialization per draft-miller-ssh-agent using `ssh-key`'s encoding; zeroize buffers.
- Tests: framing unit tests + no-panic on malformed replies; integration test starting `ssh-agent -D -a <tmp>/agent.sock` (no `#[ignore]` needed if ssh-agent exists; skip with a message if not), add ed25519/rsa/ecdsa fixtures, list, remove, remove_all; never uses `SSH_AUTH_SOCK` from the environment.
- Commit `feat(core): minimal ssh-agent client`.
