# kring Plan 6: GPG keys (via the gpg binary)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manage the user's GnuPG keys (list public/secret keys with subkeys, uids, validity, expiry, trust; create, import, export public/secret armored, delete, change passphrase) by driving the `gpg` binary, with passphrases entered in kring (loopback pinentry), backups before destructive operations, the session-remembered passphrase and the progress modal.

**Architecture:** `kring-core::gpg` drives `gpg --batch --with-colons --fixed-list-mode` (listing) and `gpg --batch --pinentry-mode loopback` with `--command-fd`/`--status-fd` for interactive operations (passwd) or `--passphrase-fd` for single-passphrase operations. `GNUPGHOME` respected; tests run with a temp `GNUPGHOME` and their own `gpg-agent` (`--homedir` scoped; killed via `gpgconf --homedir <tmp> --kill all`). Worker `worker_gpg.rs`; UI area "GPG keys".

**Spec:** `docs/superpowers/specs/2026-11-15-kring-design.md` section 6.8 (and 2.6). User decision: drive the `gpg` binary.

## Findings (user's system)

- GnuPG 2.4.8, libgcrypt 1.11. The user's keyring has 2 public keys and 0 secret keys (counts only). `pinentry-qt` is the system pinentry (kring must use loopback so no Qt window appears). No `allow-loopback-pinentry` setting found in `~/.gnupg/gpg-agent.conf` (GnuPG 2.4 allows loopback by default; detect and explain if refused).

## Global Constraints

- All previous constraints (no GUI toolkits linked, SecretValue/zeroize, no secrets in events except dedicated ones, English, rustdoc, early returns, UPPER_SNAKE, no long dash, rustfmt, Conventional Commits without AI attribution).
- **Never run gpg against the user's real `~/.gnupg` in tests/tools**: every test sets `GNUPGHOME` (and `--homedir`) to a temp dir with mode 0700 and kills its agent at the end (`gpgconf --homedir <dir> --kill all`, Drop guard). The real `~/.gnupg` is only used by the app in normal use.
- Passphrases are passed through a pipe fd (never argv, never env); loopback pinentry (`--pinentry-mode loopback`); stdin/stdout/stderr of gpg captured; stderr messages are returned without passphrases; output size capped.
- Child processes: absolute path resolution of `gpg` (PATH lookup once, refuse if missing with a clear error), timeouts (30 s for listing/import/export, 120 s for key generation), killed on timeout.
- Destructive: delete secret+public requires full fingerprint (`--batch --yes --delete-secret-and-public-key <FPR>`); before deleting or changing a passphrase, back up with `gpg --export-secret-keys --armor` (age-encrypted, since it is secret material even if protected) and `--export --armor` into `BackupManager` (sensitive sources, reason `delete-gpg-key` / `change-gpg-passphrase`).
- Export secret: armored to a user-chosen path with create_new 0600; requires the key passphrase (loopback).
- Trust and key signing are out of scope (spec non-goal).

## Review Focus

1. No test or tool touches the real `~/.gnupg` or the user's gpg-agent.
2. Passphrases never in argv/env/logs/events; fds closed; zeroized buffers.
3. Colon-format parser robust (fields per gnupg doc/DETAILS; unknown records ignored; no panic).
4. Delete/passwd backed up first (age), fail closed on backup errors, full-fingerprint delete.
5. Wrong passphrase / bad passphrase status lines map to shared constants so the UI reopens dialogs (Plan 4 machinery).

### Task 2: Key operations
**Files:** `crates/kring-core/src/gpg/ops.rs`.
- `create_key(&GpgRunner, uid: &str, algo: GpgAlgo /* Ed25519Cv25519 default | Rsa3072 | Rsa4096 */, expire: Option<&str> /* e.g. "2y" */, passphrase: Option<&SecretValue>) -> Result<GpgKey>` (`--quick-gen-key uid algo usage expire`, then `--quick-add-key` for the encryption subkey when needed).
- `import_keys(&GpgRunner, armored_or_binary: &[u8]) -> Result<ImportReport { imported, unchanged, secret_imported, fingerprints }>` (parse `IMPORT_OK`/`IMPORT_RES` status lines).
- `export_public(&GpgRunner, fpr) -> Result<String>` (armored), `export_secret(&GpgRunner, fpr, dest: &Path, passphrase) -> Result<()>` (create_new 0600).
- `change_passphrase(&GpgRunner, manager, fpr, old, new, backup_passphrase) -> Result<BackupInfo>`: backup (export secret armored with old passphrase -> age), then `--passwd` driven via `--command-fd` answering `GET_HIDDEN passphrase.enter` twice in order (old then new); map `BAD_PASSPHRASE` status to `MSG_WRONG_GPG_PASSPHRASE`.
- `delete_key(&GpgRunner, manager, fpr, passphrase_for_backup: Option<&SecretValue> /* key passphrase to export secret for backup */, backup_passphrase) -> Result<BackupInfo>`: backup public (+ secret if present) then delete by full fingerprint; verify the manifest before deleting.
- Constants: `MSG_WRONG_GPG_PASSPHRASE`, `MSG_GPG_PASSPHRASE_REQUIRED`, `MSG_LOOPBACK_REFUSED` (agent refuses loopback: explain `allow-loopback-pinentry`).
- Tests in temp homedirs for each op incl. wrong passphrase and backups.
- Commit `feat(core): gpg key operations with backups`.
